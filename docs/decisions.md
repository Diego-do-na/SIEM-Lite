# Design decisions: API, analytics and dashboard

Each entry: context, decision, alternatives and why they lost, and what it costs us.

## 1. Cognito for authentication (not a Terraform-generated API key, not IAM/CLI credentials)

- **Context.** The dashboard needs authenticated users, and 1.1 will add admin-only actions.
- **Decision.** Cognito user pool with groups `admin` / `viewer`, Authorization Code + PKCE, JWT validated by
  API Gateway.
- **Alternatives.**
  - *API key generated by Terraform*: lands in state and in the browser, one shared secret, no identities,
    no per-user revocation, no roles for later.
  - *AWS CLI/IAM credentials as auth*: not usable from a browser without Cognito identity pools anyway, and
    ties the product to AWS accounts.
- **Cost.** More Terraform (pool, client, domain, groups) and a hosted-login redirect flow in the SPA.
  Free tier covers the volume.

## 2. HTTP API (not REST API)

- **Decision.** API Gateway HTTP API with a JWT authorizer.
- **Why.** Cheaper, lower latency, native JWT authorizer, simpler CORS. REST API features we would pay for
  (API keys, usage plans, request validation models, WAF attachment) are not needed in 1.0.
- **Consequence.** HTTP APIs have no mock integration, so `/health` is a trivial fourth Lambda. Throttling is
  stage-level in practice.

## 3. Incremental ETL instead of a weekly Glue batch

- **Context.** The original design batched raw JSON into Parquet weekly (small-files argument). That made
  the dashboard stale for up to a week and kept two copies of every incident.
- **Decision.** The exporter Lambda, already triggered by the stream, writes the raw event and one curated
  JSON line per incident. Athena reads the curated lines through a Glue table with **partition
  projection**. No job, no crawler, no workflow.
- **Why.** At this volume (tens to hundreds of incidents per month) one tiny object per incident costs
  cents, data is queryable immediately, and the dashboard can be live. The small-files problem is real at
  scale, so it is deferred, not ignored: 1.1 adds a periodic compaction job to Parquet.
- **Raw vs processed is not redundancy.** Raw is the immutable original (audit, reprocessing); processed is
  a curated, flat projection shaped for queries.
- **Cost.** About USD 0.04/month versus about USD 0.3 to 0.5 for the Glue job and crawler.
- **Partition layout (found by testing on real AWS).** The first version used `year=/month=/day=` projected
  over 2025–2035: about 4,000 possible partitions. Queries that filtered only on `timestamp` made Athena list
  every one of them in S3, and a table with 7 tiny files took 14 to 100 seconds per query. The fix is a single
  date partition (`day=YYYY-MM-DD`, projection type `date`) plus a mandatory `day >= ...` predicate in every
  query, computed in code from the requested window, so Athena lists only the days it needs. Rule: with
  partition projection, always filter on the partition column. Queries that time out are also stopped
  (`StopQueryExecution`) so they do not keep running.

## 4. Cache keyed by data version

- **Problem.** The dashboard polls `/stats`; counting incidents reads the whole partition each time. Athena
  reports cost money and take seconds.
- **Decision.** A DynamoDB cache table (TTL) stores each answer with the `lastIncidentAt` it was computed
  for. It is valid while the version is unchanged (bounded by `max_age`) or while younger than a 60 s floor.
- **Why not a fixed TTL only.** A fixed TTL is either stale after an incident or recomputes needlessly when
  nothing changed. Versioning gives both freshness and cheapness, and the floor protects against bursts.
- **Alternatives.** Atomic counters updated by the stream (exact and O(1), but more moving parts; 1.1 if
  scale demands it); CloudFront/API Gateway caching (cannot key on data version).

## 5. Pagination: keyset cursor merged across severities

- **Decision.** The table is partitioned by severity; the list is the merge of four newest-first queries
  with an opaque cursor `{timestamp, severity index}`.
- **Why.** Offset pagination is unstable while new incidents arrive and O(n) deep in the list. A keyset
  cursor is stable and cheap, and the severity index in the cursor resolves ties on the same second.
- **Filters** (`ip`, `user`, `technique`) are `FilterExpression`s, bounded by 50 pages. Full-text/ad-hoc
  search at scale belongs in Athena (1.1).
- **History.** The dashboard has a feed (latest 15) plus a History section with filters and "Load more", so
  it is not limited to the last N incidents.

## 6. Analytics in Athena with fixed queries

- **Decision.** Four fixed reports; the client chooses only `report` (whitelist) and `days` (7/30/90).
- **Why.** Ad-hoc SQL from the client is an injection and cost risk. Fixed SQL makes the cost per call
  predictable and the surface auditable. Aggregation in the browser was rejected: it would force shipping
  all rows to the client and discard the point of having an analytics tier.
- **Guard rails.** Workgroup scan cutoff 1 GiB; results cached; 29 s Lambda timeout returns 504, not hang.

## 7. Two separate defenses: token validation and input validation

See [security.md](security.md). API Gateway answers "who are you"; each Lambda answers "is this input
safe". Neither replaces the other.

## 8. One Lambda per resource group, not one monolith

`incidents`, `stats`, `analytics`, `health` have different permissions, timeouts (3–29 s) and
dependencies. Separate roles keep least privilege real (the `incidents` function cannot touch Athena or the
cache). Shared helpers live in `backend/shared`, packaged with each function.

## 9. One Terraform file per service

`api.tf`, `cognito.tf`, `athena.tf`, `glue.tf`, ... Each file carries its own locals. Easier to review
in a PR and to find in an interview. `iam.tf` is the one cross-cutting file by design (all roles and
policies in one place for audit).

## 10. Abuse control

Stage throttling (10 rps, burst 20), Athena cutoff, cache floor, small Lambdas. CloudWatch alarms on API 5XX,
API 4XX bursts and Lambda errors, and an AWS Budget, notify by email (the alarms use their own SNS topic:
CloudWatch cannot publish to a topic encrypted with the AWS managed key, and a CMK is 1.1). WAF is 1.1.

## 11. Frontend: static SPA on private S3 + CloudFront

- **Decision.** Vanilla JS, no build step, no npm dependencies (nothing to audit or patch in the supply
  chain). Hosted from a private bucket through CloudFront with Origin Access Control and security headers.
- **Rejected: desktop app.** It does not add security: the API is public either way, and it adds
  distribution and update burden.
- **Rejected: public S3 website.** No HTTPS custom headers, public bucket.
- **Local development** uses `http://localhost:5173`, the default of `dashboard_origins`.
- **CSP and CORS dependency cycle.** The CSP needs the API URL (`connect-src`) and the API CORS needs the
  CloudFront origin, which would be a cycle in Terraform. Broken with a regional wildcard,
  `https://*.execute-api.<region>.amazonaws.com`, in `connect-src`. Trade-off: the page may call any
  API Gateway in that region, not only ours. Accepted for 1.0; the real protection is still Cognito JWT
  validation on the API. A custom domain for the API (DEBT) removes the wildcard.
- **Caching.** Managed-CachingOptimized (so compression works) plus `Cache-Control: no-cache` on every
  object, so CloudFront and browsers revalidate with the ETag. `aws_s3_object` uses `filemd5` as etag,
  so a changed file is re-uploaded by `terraform apply` and shows up without manual invalidations.
- **`config.js` generated by Terraform** (API URL, Cognito client, login URL), so the deployed page can
  never point at a stale stack. The local `frontend/config.js` stays gitignored for development.
- **No `force_destroy`** on the frontend bucket: every object is Terraform-managed, so `destroy` works.

## 12. Honest error handling

Handlers log with `logger.exception` and return a generic 500 plus `requestId`; input errors are 400 with a
precise message. The same id is in the API access log, so a user report can be traced to the exact log line.

## 13. Checkov exceptions are explicit

Global skips live in `.checkov.yaml` with reasons; one-off exceptions are inline next to the resource.
Routes are split into `public` and `protected` resources so a route accidentally left without
authorization is still flagged by `CKV_AWS_309` instead of being hidden by a blanket skip.

## 14. The dashboard explains its charts with rules, not a model

- **Problem.** A chart that only gets bigger when expanded teaches nothing; an analyst also needs to know how to read it and what in it matters.
- **Decision.** Every expanded card shows how to read it, a few findings and the exact numbers (`frontend/js/explain.js`). The findings are plain rules over the figures on screen (maximum, share, first half against second half), not text from a model.
- **Why.** Each sentence can be checked against the table beside it, costs nothing per view, works offline with demo data and cannot invent a fact. Bedrock already writes the one narrative that needs judgment, the per-incident triage.
- **Trade-off.** The rules are written by hand per chart, so a new chart needs its own. Acceptable at this size.

## 15. Alternatives left for later

MFA, WAF, CMKs, a compaction job, atomic counters, admin actions (`POST /actions`, admin group only). See
[roadmap.md](roadmap.md).
